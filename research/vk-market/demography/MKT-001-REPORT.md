## 0. Что это и чем не является

Это **community demographic proxy** — агрегированный состав публичных участников
официальных VK-сообществ игр из shortlist EXP-003. Это **не player demographics**:
члены сообщества — самоотобранная тонкая прослойка аудитории приложения
(см. §5: сообщества составляют 0.01–1% от публичной метрики `members_count`
приложений). Никаких выводов «механика X для пола/возраста Y» без оговорок §6.

Приватность: страницы `groups.getMembers` агрегировались потоково
(получил страницу → обновил счётчики → отбросил записи). В Git — только агрегаты.
Ячейки `<20` в возрастных/городских срезах подавлены (`suppressed` / свёрнуты в остаток).

## 1. Метод (кратко)

- Токен — только локальный `.env` (`VK_SERVICE_TOKEN`, Bearer-заголовок, нигде не печатался
  и не коммитился). API version `5.199` — та же, что у действующего collector.
- Rate: старт запросов не чаще 1/1.05 s; TLS verification включён всегда (truststore).
- `groups.getById` (1 батч-запрос: существование, `is_closed=0`, `members_count`)
  + `apps.get extended=1` на каждый app-кандидат (доказательство официальности:
  `author_owner_id == -group_id`).
- `groups.getMembers` с `fields=sex,bdate,city,country`, страницы по 1000,
  полный проход доступных public members (потолок offset 10000 не понадобился —
  крупнейшая группа 1425).
- Возраст — только по `bdate` с годом рождения, на дату capture; buckets
  `<18 / 18–24 / 25–34 / 35–44 / 45–54 / 55+`.
- Код: `tools/vk_demography/collect.py`, проверки: `tools/vk_demography/verify.py`.
  Rate-лог (`artifacts/vk-demography/<stamp>/requests.jsonl`) — только метки времени/
  параметры/статусы, gitignored, не коммитился.

## 5. Coverage и качество proxy (честно)

- **sex**: coverage 1.0 везде — поле `sex` присутствует у всех 2739 обработанных записей
  (значений вне 1/2 не встречено). Самый надёжный срез proxy.
- **age-year**: coverage 0.27–0.62 по сообществам (пул 0.44–0.62). Больше половины записей
  года рождения не дают — возрастной профиль построен на меньшинстве.
- **city**: coverage 0.60–0.87, но география сильно фрагментирована: города с n≥20
  нашлись только в двух крупнейших сообществах (Москва/СПб лидируют в обоих).
  Остальное — длинный хвост, опубликованный только как coverage.
- **country**: поле не встречено ни разу (как и предсказывал smoke-test).
- **Размер proxy**: сообщества — 0.01–1% от app-аудиторий; arrow-lane фактически держится
  на одной группе (Разбери Кубик, 90 записей), две другие arrow-группы крошечные
  и API-недоступны.

## 6. Пригодность proxy (вывод, не решение)

1. Как грубый межмеханический ориентир по **sex-составу активных сообществ** proxy
   пригоден с оговорками: sort/merge-пулы (1450/469) заметно более женские (~81–82% F),
   чем match3-пул (55% F, в основном за счёт Гранд Тура); arrow (70% F, n=90) —
   единичная точка, а не оценка lane.
2. По **возрасту** proxy слабый: coverage <50% в большинстве групп, пулы маленькие;
   видно лишь, что ядро с известным годом — 25–44 (sort/match3) и 25–55+ (merge),
   а arrow-точка смещена в 55+ на n=56 — интересно, но недостаточно для выводов.
3. По **географии** proxy почти неинформативен за пределами «Москва/СПб первые
   в крупных сообществах».
4. Для выбора аудитории/темы Arrow-Roguelite этот proxy — **вспомогательный фон**,
   а не основание: покрывает самоотобранные доли процента и молчит про молчаливое
   большинство игроков. Так и использовать.
