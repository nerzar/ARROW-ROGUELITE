Сейчас проект находится в фазе исследования и проектирования. Игра/MVP ещё не разрабатывается.

Текущие направления:
- исследование VK Games через VK API;
- холодная оценка аудитории и конкурентов;
- разбор референсов;
- механика Arrow/Tap Away + внешний target layer + возможный roguelite;
- оценка ассетного бюджета и визуальной темы.

## Проверка

Пока стек игры не выбран, общие проверки задаются в каждой task-карточке.

Для VK research-задач минимум:
- не раскрывать `VK_SERVICE_TOKEN`;
- `.env` и raw artifacts не должны попадать в Git;
- API collector должен быть воспроизводимым;
- фактические поля API важнее предположений из документации;
- итоговые публичные данные должны быть агрегированными там, где работа касается пользовательской демографии.

## Правила проекта

- STRICT RULE: проектные, архитектурные, игровые и визуальные решения не считаются принятыми без явного подтверждения пользователя.
- STRICT RULE: исполнитель не делает merge в `main` самостоятельно.
- STRICT RULE: секреты VK, `.env` и токены никогда не коммитятся и не попадают в отчёты/логи.
- AGREED FOR NOW: рабочее название — **Magic Arrow**.
- AGREED FOR NOW: сначала максимально продумываем и исследуем продукт, затем отдаём реализацию агентам.
- AGREED FOR NOW: VK-аудиторию и тему игры выбираем по данным, а не по предположениям.
- IDEA: базовая механика — Tap Away / Arrow Puzzle, где освобождённая стрелка продолжает полёт и взаимодействует с внешней целью; поверх рассматривается roguelite-слой. Это ещё не финальный дизайн.
- IDEA: monsters / magic / Cupid / treasure и другие темы остаются гипотезами до исследования аудитории.

## Что особенно дорого

- генерация большого количества уникальных изображений;
- дорогие модели без необходимости;
- повторное исследование уже собранных данных;
- массовые API-запросы без плана и снапшотов;
- чтение всего репозитория каждым новым агентом;
- несколько агентов, делающих одну и ту же работу.
