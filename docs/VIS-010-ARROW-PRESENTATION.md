# VIS-010 — Arrow Presentation Spec

STATUS: **PROPOSAL FOR PLAYTEST** (спек, не решение; вариант не объявляется принятым).
TYPE: visual spec, **НЕ implementation**. `board-renderer.js`, gameplay и projection не меняются.

Актуализировано: 17 сентября 2026.

## 0. Рамка

Текущий вид стрелок пользователем **не принят**: glow-polyline с `shadowBlur`,
белым inner-core (`lighter`, alpha 0.22) и пунктиром для blocked читается как
«светящаяся лапша», особенно на длинных paths. Этот спек предлагает замену на
уровне presentation: та же геометрия (`cells → cellCenter → polyline`), тот же
board plane и перспектива (FIX-021), другой визуальный язык.

Связанные документы: `docs/VISUAL-DIRECTION.md`, `docs/ARROW-VISUAL-PROGRESSION.md`
(board state сдержан, projectile state зрелищен), FIX-021 (plane неподвижен,
перспектива через `localScaleAt`), EXP-013 (Stone Pin: геометрически свободна,
механически untappable, тап — no-op без HP-стоимости).

Мокап: `docs/VIS-010-contact-sheet.html` — открывается в браузере без сборки,
сетка 3 подхода × 8 состояний, везде один и тот же длинный S-path.

## 1. Общий инвариант (одинаков для всех подходов)

Чтобы подходы сравнивались честно, ниже зафиксировано то, что **не варьируется**.

### 1.1. Геометрия и перспектива

- Path стрелки — та же ломаная по центрам клеток, что сейчас. Спек меняет только
  отрисовку, не точки.
- Все ширины задаются в единицах `S` = `localScaleAt` в клетке наконечника
  (перспективно-чувствительный масштаб, FIX-023): дальняя/верхняя стрелка тоньше,
  ближняя/нижняя — массивнее. Никаких абсолютных px в спеке.
- Наконечник всегда рисуется в перспективном масштабе своей клетки и поворачивается
  по **отрисованному** (rotateUV) направлению, не по логическому.

### 1.2. Arrowhead (обязательный минимум)

- Залитый кайт (треугольник с вогнутым задним срезом, не «галочка» из линий):
  длина `0.55S`, ширина `0.62S` — крупнее нынешних `0.42S`, потому что тело
  становится тише и наконечник несёт чтение направления единолично.
- Контраст наконечника к камню ≥ 3:1 в каждом состоянии (кроме dead/removing).
- Никаких свечений, вынесенных за габариты наконечника более чем на `0.10S`.

### 1.3. Бюджет перекрытия (anti-noodle rule)

- Постоянный ореол/подсветка вдоль тела — **запрещены** во всех подходах.
  `shadowBlur` вдоль path не используется вообще.
- Любой эффект состояния не выходит за коридор `±0.55S` от оси path
  (соседний path на типичной плотности — на расстоянии `≥1.0S`, запас двойной).
- Анимация на board — максимум **один** движущийся элемент на стрелку
  (pulse/march), только в активных состояниях (hover, targeting, firing);
  в покое (blocked/free/pin) всё статично.

### 1.4. Палитра камня

- База — каменные/костяные тона доски, не неон: тело темнее или светлее фона
  минимум на шаг, акцент — один приглушённый металл (золото/бронза) для
  «магической гравировки». Яркие elemental-цвета на board запрещены
  (см. `ARROW-VISUAL-PROGRESSION.md`: элемент раскрывается после выхода).
- Исключение — короткие one-shot вспышки hit/firing (≤300 мс), им разрешён
  тёплый белый/золотой.

### 1.5. Восемь состояний (определения)

| # | Состояние | Значение |
|---|---|---|
| 1 | `blocked` | Путь до выхода занят; тап = ошибка/штраф |
| 2 | `free` | Путь свободен, тап выпустит стрелку |
| 3 | `hover/selected` | Курсор/фокус на стрелке (десктоп hover, мобайл — последний тап-превью) |
| 4 | `targeting` | `free` + её `arenaDir` смотрит на живую цель (сегодняшний `aims`) |
| 5 | `firing` | ~300 мс полёта после тапа: тело уходит с board |
| 6 | `hit` | ~250 мс подтверждение попадания на цели (отголосок на месте выхода) |
| 7 | `dead/removing` | Стрелка покинула board / растворяется (место освобождается) |
| 8 | `Stone Pin` | Камень врага: геометрически свободна, untappable, тап — silent no-op |

`hover` и `targeting` могут совпадать — тогда действует правило слоёв из §5.

## 2. Подход A — Segmented Magical Rail («наборная инкрустация»)

**Идея.** Тело стрелки — не линия, а ряд каменных/металлических сегментов-плашек,
вложенных в плиту, как рельс из отдельных звеньев. Зазоры между сегментами дают
«воздух»: длинный path читается как пунктир инкрустации, а не как сплошная лапша.
Направление задают сужение сегментов к голове + наконечник.

**Конструкция (токены):**

- Сегмент: скруглённая плашка длиной `0.34S`, шириной `0.30S`, зазор `0.16S`.
- Сегменты слегка сужаются к голове (последний — `0.22S`), создавая перспективу
  движения даже в статике.
- Кромка сегмента: тёмная обводка `0.03S` (эффект «врезано в камень»).
- Наконечник — кайт из §1.2, тот же материал, что сегменты, но на полтона светлее.

**Состояния (тот же длинный path):**

1. `blocked` — сегменты плоские, в тон камня (контраст минимальный, но силуэт цел);
   зазоры широкие (`0.20S`), ритм «спящий». Никакого красного/пунктира вдоль тела.
2. `free` — сегменты приподняты: светлая верхняя грань `0.04S` (фаска), материал —
   кость/песчаник на тёмной плите. Статично, без свечения.
3. `hover/selected` — поверх сегментов бежит **один** световой марш: 2–3 звена
   подсвечены золотом, волна идёт к голове за ~600 мс и затухает (one-shot на вход
   в hover, затем слабое статичное выделение крайних звеньев). Ореола нет —
   светится только заливка самих плашек.
4. `targeting` — звенья у головы (последние 3) залиты бронзой постоянно
   (метка «смотрит на живую цель»), остальное тело как `free`. Наконечник золотой.
5. `firing` — сегменты гаснут по очереди от хвоста к голове за ~200 мс
   (эффект «рельс отдаёт заряд»), голова-болт уже летит вне board. Хвост исчезает
   первым — направление считывается из угасания.
6. `hit` — на клетке выхода остаётся только наконечник-контур, внутри него короткая
   золотая вспышка `≤200 мс`, затем исчезает. Тела уже нет.
7. `dead/removing` — пустые гнёзда: тёмные лунки `0.20S` в местах сегментов,
   растворяются за ~400 мс (инкрустацию «вынули»). Никакого серого призрака path.
8. `Stone Pin` — поверх среднего сегмента лежит камень (круглая руна-валун
   `0.55S`, rock-brown из нынешней палитры), звенья под ним затемнены; рядом —
   бейдж `Nt` (остаток пина). Геометрия свободна, но камень буквально придавил
   рельс — метафора untappable без красного «ошибка».

**Плюсы:** длинный path дробится зазорами (главное лекарство от лапши);
сегменты естественно ложатся в перспективу (масштаб через `S`); firing/hit/dead
рассказываются тем же языком (заряд → вспышка → гнёзда).

**Риски:** больше draw-примитивов на стрелку (~длина/0.5S прямоугольников);
на мелких клетках сегменты могут слиться в линию — нужен минимальный зазор
`max(0.16S, 1.5px)`; стиль «механического рельса» может спорить с organic-фэнтези.

## 3. Подход B — Engraved Groove + Running Pulse («гравировка в камне»)

**Идея.** Стрелка — это **выемка** в плите, а не объект на ней: тёмная гравированная
канавка с резной кромкой. Магия видна только как тонкая светлая нить на дне
канавки и редкий бегущий импульс. Максимальное «часть камня», минимальный шум.

**Конструкция (токены):**

- Канавка: тёмная заливка шириной `0.30S`, края — резная фаска: внутренняя тень
  со стороны света `0.05S`, светлый скос с противоположной `0.03S`.
- Нить на дне: приглушённое золото, ширина `0.07S`, alpha 0.75. Это единственный
  «светящийся» элемент, и он **внутри** канавки, наружу ничего не выходит.
- Одна шеврон-насечка возле головы (уголок `0.30S`), указывает направление вместе
  с наконечником.
- Наконечник — кайт из §1.2, рисуется как углубление с золотой кромкой по режущим
  сторонам (читается и как тень, и как металл).

**Состояния:**

1. `blocked` — канавка есть, нити нет (пустая резьба). Самый тихий вид из всех
   подходов: заблокированное буквально «не заряжено».
2. `free` — нить на дне зажигается (alpha 0.75), статично. Больше ничего.
3. `hover/selected` — по нити идёт **один** pulse: яркая точка `0.16S` бежит
   от хвоста к голове ~500 мс, за ней нить на 1 с становится ярче (alpha 1.0),
   затем возвращается к `free`. Цикла нет — только отклик на вход/тап-превью.
4. `targeting` — нить в последней трети утолщается до `0.11S` и теплеет
   (бронза вместо золота), шеврон-насечка заливается тем же. Эффект «канавка
   ведёт к цели», без выхода за коридор.
5. `firing` — pulse ускоряется и вытягивается: яркий отрезок нити `1.2S` уходит
   к голове за ~150 мс и срывается за край board вместе с болтом; канавка за ним
   гаснет от хвоста (нить alpha → 0 следом за pulse).
6. `hit` — голова канавки (последние `0.8S`) вспыхивает золотом на ~200 мс
   (дно, не ореол) и гаснет. Кромка остаётся.
7. `dead/removing` — канавка «запесочивается»: дно светлеет к тону камня за ~400 мс
   (нить уже погасла во firing), остаётся едва видимый след резьбы, затем ничего.
   Место читается свободным раньше, чем след исчез полностью (след — ниже порога
   интерактивного контраста с первых 150 мс).
8. `Stone Pin` — поперёк канавки лежит каменная нашлёпка-пломба (`0.60S`,
   rock-brown, с трещинами-рисками): нить под ней оборвана (разрыв нити = знак
   untappable, сильнее любого бейджа), поверх — счётчик `Nt`. Пустая канавка +
   пломба не путается с `blocked` (там канавка цела, но без нити).

**Плюсы:** strongest «часть камня» (выемка, а не наклейка); в покое всего два
тона — длинные paths почти исчезают в плиту, доска дышит; направление дублировано
трижды (сужение исключено, но есть шеврон + наконечник + бег pulse к голове);
разрыв нити — самая честная метафора пина.

**Риски:** на светлой теме тёмная канавка может читаться тяжелее светлой инкрустации
(лечится глубиной фаски, не шириной); pulse требует аккуратного тайминга, чтобы не
стать «бегущей строкой»; гравировка менее игрушечная — проверить на cozy-тоне.

## 4. Подход C — Solid Core + Sparse Directional Markers («тихий стержень»)

**Идея.** Компромисс между нынешней линией и гравировкой: тело — тонкий матовый
стержень без всякого свечения, а направление несут редкие шевроны-маршрутки.
Минимум нового языка, максимум совместимости с текущим рендером.

**Конструкция (токены):**

- Стержень: сплошная матовая заливка шириной `0.20S` (уже нынешних `0.27S`),
  без обводки-свечения, края жёсткие. Ноль `shadowBlur`, ноль inner-core.
- Шевроны: максимум 3 на path (у хвоста, середины, головы), размер `0.34S`,
  тот же тон, что стержень, но на полтона светлее. На коротких стрелках — 1.
- Наконечник — кайт из §1.2, единственный элемент с мягкой тенью
  (радиус `≤0.10S`, только под наконечником, не вдоль тела).

**Состояния:**

1. `blocked` — стержень и шевроны в тоне камня с alpha 0.45. Тише нынешнего
   пунктира, но силуэт цел (пунктир-для-blocked упраздняется как класс).
2. `free` — стержень alpha 1.0, кость/металл; шевроны чуть светлее стержня.
3. `hover/selected` — под стержнем появляется плоская подложка-фаска
   (ширина `0.34S`, alpha 0.25, без размытия — именно плашка, не glow),
   шевроны заливаются золотом. Статично после 150 мс fade-in.
4. `targeting` — как `free`, но наконечник и головной шеврон золотые;
   подложки нет (не складывать с hover: правило слоёв §5).
5. `firing` — стержень стирается от хвоста (~200 мс), шевроны гаснут вместе
   со своим отрезком; последний кадр — один летящий шеврон у края.
6. `hit` — короткий золотой шеврон-вспышка на клетке выхода (~200 мс),
   затем ничего.
7. `dead/removing` — стержень alpha → 0 за ~300 мс целиком (без лунок и следов).
   Самый дешёвый переход из трёх подходов.
8. `Stone Pin` — стержень приглушён к `blocked`-уровню, поверх середины —
   каменный узел (ромб `0.50S`, rock-brown) + бейдж `Nt`. Шевроны под узлом
   скрыты: «маршрут перекрыт».

**Плюсы:** минимальное отклонение от текущего рендера (дешёвая реализация,
меньше рисков на мелких клетках); убирает именно то, что отвергнуто (glow, core,
пунктир), ничего не изобретая заново; шевроны масштабируются числом, не размером.

**Риски:** самый слабый «каменный» характер (стержень всё ещё лежит НА плите);
длинный path остаётся сплошной линией — лекарство слабее, чем зазоры (A) или
выемка (B); шевроны на извилистых paths требуют расстановки по длине дуги.

## 5. Правила сочетаний (для будущего implementation, не для этого спека)

- `hover` + `targeting`: действует `targeting`-заливка головы + hover-отклик
  (марш/pulse/подложка) — никогда два цветовых акцента одновременно.
- `Stone Pin` перекрывает всё, кроме `firing`/`hit`/`dead` (пина нельзя снять
  выстрелом; если стрелка уже летит — пин к ней не применяется).
- `blocked`-тап (ошибка, HP-стоимость) показывает красный отклик **только**
  наконечника + короткую тряску головы (≤200 мс), никогда не перекрашивает тело:
  тело — информация, голова — действие.
- Pin-tap (no-op, без стоимости) — янтарный/каменный отклик камня-маркера,
  никогда красный (уже принято в renderer, сохранить).

## 6. Сравнение и рекомендация

| Критерий | A — Rail | B — Groove | C — Core |
|---|---|---|---|
| Часть камня | средне (инкрустация) | **сильно** (выемка) | слабо (лежит сверху) |
| Длинный path не лапша | **сильно** (зазоры) | сильно (тишина) | средне (тонко, но сплошная) |
| Чтение направления | сегменты+кайт | шеврон+кайт+pulse | шевроны+кайт |
| Перспектива | естественная | через фаску | только масштаб |
| Не лезет к соседям | да | **да** (всё внутри канавки) | да |
| Цена реализации | средняя | средняя | **низкая** |
| Риск на мелких клетках | слияние сегментов | тяжёлая канавка (светлая тема) | минимальный |

**Рекомендация исполнителя (PROPOSAL, решение за пользователем):** primary — **B**,
потому что он единственный выполняет главный пункт («ощущается частью камня»)
конструкцией, а не тоном, и даёт лучшую метафору пина (разрыв нити). Fallback — **C**,
если B на мокапе проиграет по читаемости на светлой теме или мелких досках 10×10.
**A** держать как второй финалист, если пользователь сочтёт гравировку слишком
тихой для core-механики.

Что нужно от пользователя, чтобы спек стал решением: выбрать primary (B/C/A),
подтвердить токены §1.2–§1.3 (размеры наконечника и коридор `±0.55S`) и ответить,
допустим ли pulse в `hover` на мобайле (тап-превью) или hover там статичен.

## 7. Acceptance для будущего implementation-таска

1. Длинный path (≥6 клеток) в `free` не имеет непрерывного свечения вдоль тела
   (проверка скриншотом + чтением кода: нет `shadowBlur` на теле).
2. Направление определяется по одному кадру без чтения хвоста (тест: наконечник
   + дублирующий маркер видны при любом состоянии, кроме dead).
3. Эффект любого состояния не касается соседнего path (авточек: расстояние от
   отрисованных примитивов до чужой оси ≥ `0.45S`, по аналогии с VIS-007 layout).
4. Ширины/наконечник масштабируются через `localScaleAt` клетки головы
   (даль/близь визуально различаются на трапеции FIX-021).
5. `Stone Pin` визуально отличим от `blocked` (тест: скриншот-тест пары).
6. Pin-tap отклик не красный; blocked-tap отклик только на голове.
7. Ни один кадр board-состояния не содержит больше одного движущегося элемента
   на стрелку.
