## 1. Seed Analyzer

Для доски и её canonical order (сохранённое решение генератора) выдаёт:

- число стрел N/E/S/W и initial free по направлениям (+ id);
- direction sequence, например `EWEWWWESWENEEWWESESWE`;
- по каждому шагу: removed dir, free before по направлениям, newly-free (id + dir), remaining по направлениям;
- branch points (свободно > 1 стрелы) и direction branch points (свободные смотрят в ≥ 2 стороны);
- независимую от порядка раскладку по слоям разбора: в каком слое впервые доступно каждое направление.

JSON (`--json` / `--out`) — те же поля (`SeedAnalysis`); viewer вызывает `analyzeSeed` напрямую из `dist`.

## 2. Модель encounter'а (узкая, только для этого mini-boss)

- Boss — одна цель; фаза = сторона арены + `hpUnits`; фазы идут подряд по суммарному числу попаданий.
- Tap свободной стрелки: стрелка уходит, летит в сторону арены `rotateDir(localDir, rotation)`. Совпала со стороной босса → −1 hit-unit, иначе мимо. Стрелка тратится в обоих случаях.
- `grantRotate` в фазе — заряды выдаются при входе в фазу.
- Rotate — rigid-поворот всей доски на 90° (cw/ccw — по `rotate.allow`), тратит заряд. Какие стрелки свободны, не меняется (это инвариант EXP-007, покрыт тестом); меняются только стороны арены.
- Победа: HP = 0. Поражение: доска пуста, босс жив.
- Файл encounter'а хранит `preset + seed + levelHash`; при расхождении с генератором загрузка падает с `board drift`.

## 3. Validator

`findWin` — перебор в глубину по tap и Rotate с памятью проигрышных состояний (живые стрелки + поворот + попадания + использованные Rotate) и верхней оценкой: для каждой оставшейся фазы считается, сколько живых стрелок могут смотреть на сторону босса с учётом доступных к тому моменту поворотов. Ответ помечен `proven`; при исчерпании бюджета узлов вернётся `UNKNOWN`, а не «нет».

`validateEncounter` отвечает на вопросы: победа существует? победа без Rotate? победа с ≤ k Rotate (k = 0..выдано)? минимум Rotate; максимум урона без Rotate; пример winning sequence с трассой.

Проверка корректности: на ~400 случайных маленьких encounter'ах `findWin` и `maxHits` сравниваются с полным перебором без отсечений; найденные последовательности переигрываются через `EncounterState`. Мутационная проверка: испорченная верхняя оценка и «попадание без учёта Rotate» ловятся тестами.

Скорость: provisional encounter валидируется целиком за ~70 мс; скан 3000 seed'ов с перебором 12 HP-разбивок и симуляциями — ~16 с.

## 4. Shortlist

Сцена из `docs/GAME-CONCEPT.md` §6: фаза 1 — босс справа (E), фаза 2 — сверху (N) и выдаёт 1 Rotate (cw и ccw разрешены).

Скан: `medium` (8×10), seeds 1..3000. Фильтры: 12–24 стрелы; ≥ 1 свободная E-стрела на старте; для HP-разбивки `h1 ∈ 2..4`, `h2 ∈ 2..6` validator должен **доказать**, что без Rotate победы нет, и найти победу с 1 Rotate. Прошло 1876 досок. Из подходящих разбивок берётся самая длинная с `h1 ≥ 3` и суммой ≤ 9.

Метрики ранжирования (веса provisional, это инструмент сортировки для человека):

- `sloppy ph.1 ok` — доля симуляций с небрежной фазой 1 (случайные тапы), после которых победа ещё возможна;
- `greedy win` — доля побед игрока «бей, если можешь; Rotate, если он даёт попадание; иначе случайный тап»;
- `N-facing at ph.2` — сколько живых стрелок смотрит на N к началу фазы 2 (хотим 1–2 при `h2` = 5: «боеприпасы есть, но не туда»);
- `after Rotate` — лучший запас N после одного поворота (хотим `h2`+2…+4);
- `cw / ccw wins` — выигрывает ли поворот в эту сторону сразу в начале фазы 2;
- стартовая доступность E и доля direction branch points.

Как читать группы:

- **#1, #4, #6** — на N ровно одна стрела: нехватка видна сразу после первого попадания в фазе 2; лучший поворот даёт 8 стрел на N.

## Provisional seed: medium 2908 (#1)

```
boss HP 9: фаза 1 — E, 4 hp; фаза 2 — N, 5 hp, Rotate ×1
win (any):           YES
win without Rotate:  NO (proven), максимум 5/9
win with <= 1:       YES, min Rotates = 1
```

Сыграно в viewer настоящими кликами: 4 попадания E → босс уходит наверх, выдан Rotate; одна N-стрела → на стороне N `0 / 0`; Rotate cw → на стороне N `8 / 5` → 4 попадания → победа. Тот же старт без Rotate (тапы подряд до пустой доски) заканчивается поражением при HP 4/9.

## Что открыто (решать пользователю)

- Rotate: cw и ccw или одно направление; бесплатный ли, сколько зарядов.
- Стоит ли mini-boss быть таким прощающим: у всех топ-кандидатов небрежная фаза 1 не ломает победу. Если нужен острый момент, фильтр можно сменить на «работает только одна сторона поворота» (#7–#10) или поднять `h2`.
- Стрела мимо босса просто тратится; нужна ли ей какая-то роль — вопрос дизайна.
- Поражение сейчас наступает только на пустой доске; раннего «ты уже не можешь победить» в правилах нет (есть только в debug-индикаторе).
- Веса ранжирования шорт-листа произвольные; вершина рейтинга плоская (95.9–99.5), выбирать стоит глазами в viewer.

## Ограничения spike

- `findWin` экспоненциален в худшем случае; для досок до ~25 стрел хватает бюджета, для больших ответ может быть `UNKNOWN`.
- Только одна цель, одна сторона за фазу, 1 попадание = 1 hit-unit. Никаких мобов, Ricochet, gear.
- Viewer — debug-инструмент без production-архитектуры; `window.encounterDebug` — хук для автоматической проверки кликов.
